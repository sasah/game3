# 3. Движок

Всё, что уже сделано (картина поверх 3D-макета, глубина макета в z-буфере, нормали, маски,
увеличение-вставка), повторяет схему Pillars of Eternity и Disco Elysium. Новую технологию
изобретать не нужно; работа — во вписывании персонажей в свет картины, в бюджете проходов
для телефона и в дисциплине объёма. Подробности с источниками — в отчёте-исследовании.

## Стек

- three.js r170 из CDN через importmap, ES-модули без сборщика. *Зафиксировано\**
- WebGL2. WebGPU пока не нужен.
- Публикация — GitHub Pages из ветки по умолчанию (`.github/workflows/pages.yml`).
- Прототип движка — [`prototypes/iso/`](../../prototypes/iso/).

## Пайплайн одной локации

1. **Макет.** Простая 3D-сцена из коробок и конусов в коде ([`prototypes/iso/src/blockout.js`](../../prototypes/iso/src/blockout.js),
   [`scene.js`](../../prototypes/iso/src/scene.js)). Камера изометрическая: 45° по кругу, 30° вниз,
   ортографическая.
2. **Экспорт макета** ([`tools/export-blockout.mjs`](../../tools/export-blockout.mjs)): цветовой гид,
   глубина (24 бита в RGB), нормали, маски (вода / листва / окна).
3. **Картина поверх макета.** Модель изображений перерисовывает гид в стиле, сохраняя раскладку
   ([`tools/gen-image.py --edit`](../../tools/gen-image.py), пример — [`tools/iso-gen.sh`](../../tools/iso-gen.sh)).
   Расхождение с макетом — 10–30 px; этого хватает.
4. **Скрытый слой.** Та же картина, отредактированная: следы, тина, венок — то, что видно при свече.
5. **Глубина по картине.** Depth Anything V2 Small (ONNX, CPU, около 3 с), калибровка к глубине
   макета, нормали ([`tools/depth/`](../../tools/depth/)). Совпадает с силуэтами картины до пикселя.
   В шейдере смешивается с плоской землёй макета, чтобы ноги не проваливались.
6. **Вставки для зума.** Кроп угла картины, перерисованный в полном разрешении, с подгонкой цвета
   ([`tools/iso-gen-2.sh`](../../tools/iso-gen-2.sh)). Проявляется, когда камера наезжает.
7. **Данные сцены** (план): JSON с камерой, вектором солнца или луны, оттенком тени, палитрой,
   точками интереса, проходимостью, улицами и выходами.

Цена: картина около $0,04–0,05 при высоком качестве (gpt-image-2.5); локация с двумя стилями,
скрытыми слоями и одной вставкой — меньше доллара.

**Хранить входные данные, а не только результаты:** макеты, промпты, JSON сцен.
Поставщики меняются за месяцы, и любой шаг должен перегенерироваться у другого.

## Рендер

- **Картина** рисуется полноэкранным квадом, который пишет глубину (`gl_FragDepth`) — персонажи
  перекрываются попиксельно. Важно: запись глубины требует включённого теста глубины
  (`depthFunc = AlwaysDepth`).
- **Мировая позиция пикселя** восстанавливается из ортографической глубины. На ней держатся туман
  по высоте, тени облаков, свет свечи и места появления частиц.
- **Свет свечи** — half-Lambert с «обёрткой» по нормалям картины, ограниченный спад, тёплая дымка
  поверх (умножение на тёмной картине почти ничего не даёт).
- **Цель по проходам** (план): 3–4 вместо 8–10.
  1. Главный шейдер: картина, рельеф, вода, листва, мерцание, свеча, туман.
  2. Персонажи с тестом глубины.
  3. Одна цепочка bloom в половинном разрешении.
  4. Финальный композит: LUT, виньетка, зерно, **дизеринг** (иначе ночное небо идёт полосами).
- Интерфейс и текст — в родном разрешении: живопись апскейл прощает, буквы нет.

## Персонажи

- **Сейчас:** плоские карточки к камере из сгенерированных спрайтов (спереди и сзади, зеркалирование),
  мягкое покачивание вместо шагов, контактная тень и длинная тень от луны.
- **Позы на месте:** листы из 4 кадров одной картинкой с плавными переходами. Проверено:
  голова курит, кошка вылизывается. Стоимость около $0,05 за лист.
- **Ходьба (рекомендация исследования):** 3D-кукла из Meshy или Tripo по нашим спрайтам —
  image-to-3D, авто-скелет, около десяти готовых клипов, GLB в three.js, шейдер под живопись.
  Около $1,3–1,6 за персонажа. *Открыто* — нужен пилот на 3–5 персонажей и ключ сервиса.
- **Живность в одном ракурсе** (лягушка прыгает в воду): видео → кадры через Kling, Veo или Runway.
  Видео OpenAI (Sora) закрыто с 24.09.2026.
- **Не делать:** восемь направлений ходьбы листами из модели изображений — шаг и костюм «плывут».

**Вписать персонажа в картину** (рецепт Pillars, следующий шаг):
- карта «солнце/тень» 256–512 px в плоскости земли — под ногами персонажа масштабирует его свет и тень;
- окружающий цвет — размытый мип картины под персонажем;
- тени в оттенке нарисованной тени, контактное пятно умножением;
- палитра из 12–24 цветов с картины как LUT для персонажей;
- против скольжения ног: `timeScale = скорость / (длина шага / длительность цикла)`.

## Камера

От дешёвого к дорогому:
1. Ортографический проезд и зум — безопасны всегда.
2. «Дыхание» — несколько пикселей параллакса по глубине; ошибки глубины не видны.
3. Наезд у точек интереса со вставкой — уже работает.
4. Объёмная орбита ±5–10° по глубине картины — нужен дорисованный «задний слой», иначе края тянутся.
5. Вид «из-за хаты» — вторая картина со второй камеры того же макета и переход.

Правила Pentiment и Pillars прячут ошибки глубины: никаких троп вверх по кадру, пандусы к верху кадра,
фиксированный «север» локации.

**Переходы между локациями** — одним полноэкранным проходом: перелистывание страницы, диафрагма
волшебного фонаря, растекание туши. Края локации ведут туда, куда ведёт смысл (калитка — к ставу,
дорога — на карту Полтавщины).

## Жизнь картины

Бюджет на локацию — 2–4 несинхронных движения с разными периодами: вода (петля 6–10 с),
листва (2–4 с), окно, одно событие с живностью раз в 15–40 с. Каждое — на своём слое поверх картины.

Уже есть: рябь и блики, туман над водой, ветер в листве по маске, мерцание окон, тени облаков,
дым из трубы, лепестки вишни, мотыльки, летучие мыши, сова, светлячки.

Дальше: двухфазная карта течения Valve для воды, водомерки, лягушка, лучи от луны в четвертном
разрешении.

## Телефон

- Текстуры не больше 4096 px (8192 есть лишь у ~59% Android).
- Картина 4096² без сжатия — около 90 МБ видеопамяти; KTX2 уменьшает в 4–8 раз.
  ETC1S для картин, UASTC для нормалей и данных. *План.*
- Pixel ratio — фиксированный ярус (1,0 / 1,5 / 2,0), выбранный при старте, а не подстройка на лету.
- Нужны замеры на одном среднем Android и одном iPhone.
